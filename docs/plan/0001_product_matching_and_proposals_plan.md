# План реализации: Сопоставление позиций чека и предложение новых товаров

**Цель:** Реализация функционала каталога товаров, полнотекстового поиска через Elasticsearch, процесса модерации новых предложений, а также связывания строк чека с товарами.

## Подготовка
1. **Проверка окружения:** 
   - Убедиться, что на локальной машине установлен Docker.
   - Ознакомиться с текущей архитектурой (Hexagonal Architecture / DDD), где домены лежат в `pkg/domains`, а хендлеры, репозитории и юзкейсы в `internal/`.
2. **Изучение зависимостей:**
   - Модуль `auth` (изменение генерации JWT и структуры аккаунта).
   - Модуль `receipts` (добавление связи с продуктом в чеке).

## Возможные риски
1. **Транзакционность Outbox:** Нужно гарантировать, что Outbox Worker не будет параллельно обрабатывать одни и те же события (использовать `SELECT ... FOR UPDATE SKIP LOCKED` при чтении из Postgres).
2. **Сетевые сбои gRPC:** При вызове из `receipts` в `catalog` необходимо предусмотреть таймауты и fallback сценарии (например, ошибку "Каталог временно недоступен").
3. **Отсутствие API Gateway:** В дизайне упоминается API Gateway для валидации JWT. Если его фактически нет в коде, парсинг JWT и извлечение `X-User-Id` / `X-User-Role` придется добавить в middleware `catalog` и `receipts`. (Требует уточнения).
4. **Сложность маппинга ES:** Fuzzy matching требует аккуратной настройки анализаторов (Russian/English) в Elasticsearch для получения качественных результатов поиска.
